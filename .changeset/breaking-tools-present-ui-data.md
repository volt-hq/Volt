breaking(extensions): Tool calls and custom messages now render from presentations, UI data that every client shows the same way: bash, read, write, and edit present themselves, background jobs show as a job card with the job's live status and output under the call, and extensions can present their own tools, custom messages, and work. ([#585](https://github.com/volt-hq/Volt/issues/585))

New: `volt.registerTool({..., present})` takes a pure, synchronous `present({args, argsComplete, state, result, cwd})` that returns `{title, activity?, summary?, body?, actions?, hidden?, showsDuration?}` of `UiNode` data; `volt.registerMessagePresenter(customType, present)` presents custom messages as `{title?, summary?, body}`; and `volt.registerWorkKind(name, {..., detail})` presents a running item's detail from its title, input, progress, and output (a kind that `requires` remote capabilities is presented without its input and output, since every client sees the detail). Presenters run on the host, never in clients, and must be synchronous; a presenter that throws, returns a promise, or returns data that is invalid or larger than 64 KB (16 KB for paired devices), gets the generic presentation (the tool's name, its arguments, and its output), as do calls of tools without a presenter, including a disabled extension's. Actions in presentations send only the extension's own intents and commands, and `open_work`/`cancel_work` for its own work. The HTML export shows tool calls and presented custom messages as their presentations.

To migrate, give tools a `present` function: the built-in bash, read, write, and edit definitions no longer have `renderCall`, `renderResult`, `renderShell`, or `rendersDuration`, so code that called them must present the call instead. A tool that overrides a built-in name and brings no renderers of its own presents with the built-in presenter. Edit previews no longer read the file before the edit runs: a pending edit shows its replacements as a diff, and the file's diff with line numbers once it ran. Collapsed read calls show the first ten lines of the file.

Protocol clients: every tool item of the transcript view carries `presentation` (a `ToolPresentation`), and a custom message whose type has a presenter carries a `MessagePresentation`; the live `tool` start item carries the running call's `presentation`, and later items carry `patch` (`{summary?, body?}` patches of the trees the client holds, at most every 100 ms, so streaming output arrives as appended lines) or a whole `presentation`. A client that cannot apply a patch resubscribes after its position. Paired devices receive presentations redacted like every other frame, with image nodes as their description and within 16 KB. Work values' `detail` changes arrive as `patch` items, and a background job's live value now changes with its output, so clients read `work_output` again when the value changes instead of polling it. Render tool calls from `presentation`; the per-tool transcript fields are removed in a later release.
