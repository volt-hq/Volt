breaking(extensions): Tool calls and custom messages now render from presentations, UI data that every client shows the same way: every built-in tool and the host's own messages present themselves, and extensions present their own tools, custom messages, and work. ([#585](https://github.com/volt-hq/Volt/issues/585))

bash, read, write, edit, grep, find, ls, lsp (diagnostics as a table with severity tokens), inspect, web_search (one card per result), web_fetch (the page's details and its text as literal lines), the mcp gateway, request_user_input, jobs (a table of jobs with cancel actions), the planning tools (the plan's checklist as steps), and subagent (a timed step per child, a card per child with an action that opens its conversation) present themselves. Background jobs show as a job card with the job's live status and output under the call. Progress steps show how long each step ran. Edit previews no longer read the file before the edit runs: a pending edit shows its replacements as a diff, and the file's diff with line numbers once it ran. The HTML export presents every tool call and presented custom message.

New: `volt.registerTool({..., present})` takes a pure, synchronous `present({args, argsComplete, state, result, cwd})` that returns `{title, activity?, summary?, body?, actions?, hidden?, showsDuration?}` of `UiNode` data; `volt.registerMessagePresenter(customType, present)` presents custom messages as `{title?, summary?, body}`; and `volt.registerWorkKind(name, {..., detail})` presents a running item's detail from its title, input, progress, and output (a kind that `requires` remote capabilities is presented without its input and output, since every client sees the detail). Presenters run on the host and must be synchronous; a presenter that throws, returns a promise, or returns data that is invalid or larger than 64 KB (16 KB for paired devices) gets the generic presentation (the tool's name, its arguments, and its output), as do calls of tools without a presenter, including a disabled extension's. Actions in presentations send only the extension's own intents and commands, and `open_work`/`cancel_work` for its own work.

To migrate, give tools a `present` function and custom messages a presenter (the terminal renderers are removed; see the terminal-only extension API entry). An extension tool that takes a built-in tool's name without its own `present()` presents as the built-in, binding only the extension's own actions. `volt.registerMessagePresenter` throws for the host's message types (`work_notice`, `review`, `subagent_recovery`, `volt-plan-checkpoint`, `volt-plan-execution`), which `volt.sendMessage` also refuses. `ToolExecutionComponent` and `CustomMessageComponent` are no longer exported.

Protocol clients render tool calls from `TranscriptItem.presentation` (a `ToolPresentation`); a custom message whose type has a presenter carries a `MessagePresentation`. The per-tool fields `summary`, `path`, `args`, `details`, `output`, `outputTruncated`, `diffPreview`, and `patchPreview` are removed from the transcript view (a result's content is fetched with the `content` query), and a tool item's `text` is now its presentation's title and how the call ended (`$ npm test (completed)`). The live `tool` start item carries the running call's `presentation`, later items carry `patch` (`{summary?, body?}` patches of the trees the client holds, at most every 100 ms, so streaming output arrives as appended lines) or a whole `presentation`, and `partial` carries only `content` (`partial.details` and its `toolDetailsMaxSerializedBytes` limit are removed). A client that cannot apply a patch resubscribes after its position. Paired devices receive presentations redacted like every other frame, with image nodes as their description and within 16 KB. Work values' `detail` changes arrive as `patch` items, and a background job's live value now changes with its output, so clients read `work_output` again when the value changes instead of polling it.
