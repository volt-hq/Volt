breaking(rpc): RPC mode, JSON mode, and SDK loopback clients now speak Volt protocol 1: a client subscribes to a conversation's log by position, receives its entries and a live lane, sends intents, and runs queries. ([#585](https://github.com/volt-hq/Volt/issues/585))

`volt --mode rpc` starts with `hello` and `welcome`; a client subscribes to the conversation `welcome` names (`after: "snapshot"`, or the newest ordinal it saw to resume) and receives `snapshot`, `entry`, `head`, and `live` frames. Commands are intent frames (`{type, intentId, input}`) answered `accepted` or `rejected`, with the durable client message id as a prompt's intent id; reads are `query` frames. Streaming text, tool progress, the run phase, token use, Git and prompt-cache status, background jobs, review workflows, subagents, extension status, and dialogs are live values and items; extension errors are `notice` items. Session changes answer `accepted{conversation}` and end the old subscription `moved`. `volt --mode json` writes one local-profile subscription's frames (a snapshot, entries, live frames, then `ended`) instead of session events.

Migration: rewrite RPC clients against [docs/rpc.md](https://github.com/volt-hq/Volt/blob/main/packages/coding-agent/docs/rpc.md). State reads (`get_state`, `get_transcript`, `get_messages`, `get_session_stats`, `get_last_assistant_text`, `get_fork_messages`, `get_session_tree`, `get_pending_host_actions`) come from the subscription: the client fold (`clientFold` in `@hansjm10/volt-protocol`), the live `phase`, `usage`, and `git` values, and the `history` and `content` queries. `extension_ui_request`/`extension_ui_response` and `host_action_request`/`host_action_response` become host requests (`host_request/<id>` live values answered with `host_response`; declare the kinds you answer in `hello.accepts.hostRequests`). `invoke_ui_action`, `get_ui_actions`, and `get_commands` become intents and the `intents` query; `cycle_model` and `cycle_thinking_level` become `set_model` and `set_thinking_level` with the `models` query's `cycleScope`; `models_changed` becomes `changed{catalog: "models"}`; `subagent_get_state` and `subagent_get_transcript` become a subscription to the subagent's conversation. JSON mode readers take `entry` frames for committed messages and `live` items for streaming text. In the SDK, `RpcClient` becomes `spawnRpcClient`, `createInProcessRpcClient` becomes `createLoopbackClient`, and both return a `ProtocolClient` (`intent()`, `query()`, `prompt()`, `waitForIdle()`, `state`, `live`); `RpcTransportClient` is no longer exported, so serve other transports with `serveConnection(transport, localProfile, { host, conversation })`. RPC mode has no terminal UI: an extension's `setTheme()` reports that no UI is available. `SubagentManager` no longer takes `requestTimeoutMs`, and subagent events are the child session's events. Paired devices keep the earlier command wire until the remote profile ships.
