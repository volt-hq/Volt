breaking(extensions): Extensions can show panels of UI data above or below the editor and in fullscreen's sidebar, ask dialogs and forms that every client renders, register intents, map shortcuts to them, and complete editor tokens; `ctx.ui.getEditorText()` is now asynchronous and `volt.registerShortcut` maps a key to an intent instead of running a handler. ([#585](https://github.com/volt-hq/Volt/issues/585))

New: `ctx.ui.setPanel(name, {title?, placement?, node})` shows a `UiNode` panel (at most 32 KB; 16 per extension) whose actions and forms send only the extension's own intents and commands; `ctx.ui.dialog({title, body?, actions})` resolves with the chosen action's id and `ctx.ui.form({title, fields})` with the submitted values; `volt.registerIntent(name, {label, input?, remote?, requires?, handler})` returns the intent's name, `extension.intent.<manifest id>.<name>`, and runs `handler` with input checked against `input`; `volt.registerCompletionProvider(name, {trigger, remote?, complete})` answers the `editor_completions` query (at most 50 items within one second). `ctx.ui.notify` and `ctx.ui.setStatus` also take styled text (spans with semantic tokens), and ANSI styling in their strings becomes tokens.

To migrate, `await ctx.ui.getEditorText()`, which resolves with the text of the invoking client's editor, or `undefined` when that client has no editor or does not answer within 2 seconds. Replace `volt.registerShortcut(key, {description, handler})` with an intent and a shortcut: `const run = volt.registerIntent("my-action", {label: "My action", handler: (_input, ctx) => ...}); volt.registerShortcut(key, {description, intent: run})`; users rebind it in `keybindings.json` under the intent's name. Status items, panels, and the window title now need an extension's own context: calling them on a `withSession` replacement context throws. Status keys are 1 to 128 characters (an extension sets at most 32 items of at most 1 KB).

Protocol clients: extension status is keyed `ext_status/<extension id>/<name>` with `{extension, text}` (styled text), panels are `ext_panel/<extension id>/<name>`, `ext_title` carries `extension`, and `ext_widget` is removed. A `patch{key, ops}` live item changes a panel's node or a work item's detail in place (remote clients receive patches too). `notice.message` is styled text, `directive` adds `insert_editor_text`, and host requests add `dialog` (`{value}` answers with an action id) and `editor_text` (asked only of the invoking client, or the first attached client). Extension intents arrive as `extension.intent.<id>.<name>` frames whose input the host checks against the schema in their descriptor; paired devices reach only intents and completion providers their extension marked `remote`.
