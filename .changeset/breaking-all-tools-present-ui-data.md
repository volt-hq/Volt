breaking(extensions): Every built-in tool call and the host's own messages now render from presentations, the same `UiNode` data on every client, and tool-specific rendering is gone from the TUI, the HTML export, and the protocol. ([#585](https://github.com/volt-hq/Volt/issues/585))

grep, find, ls, lsp (diagnostics as a table with severity tokens), inspect, web_search (one card per result), web_fetch, the mcp gateway, request_user_input, jobs (a table of jobs with cancel actions), the planning tools (the plan's checklist as steps), and subagent (a timed step per child, a card per child with an action that opens its conversation, hidden while the spawn is only a confirmation preflight) present themselves. Work notices and review results present with the host's own presenters, and `volt.registerMessagePresenter` now throws for the host's message types (`work_notice`, `review`, `subagent_recovery`, `volt-plan-checkpoint`, `volt-plan-execution`). Progress steps show how long each step ran. When an extension is disabled, the TUI presents the transcript again, so the disabled extension's presenters no longer draw its tool calls and messages. The HTML export presents every tool call, including tools without a presenter.

To migrate, extension tools render only through `present()` and custom messages only through `volt.registerMessagePresenter`: `renderCall`, `renderResult`, `renderShell`, `rendersDuration`, and `registerMessageRenderer` are still accepted but no longer draw anything (they are removed in a later release), so a tool without `present()` shows as the generic card (its name, arguments, and output) and a custom message without a presenter shows as its text. `ToolExecutionComponent` and `CustomMessageComponent` are no longer exported. Protocol clients render tool calls from `TranscriptItem.presentation`: the per-tool fields `summary`, `path`, `args`, `details`, `output`, `outputTruncated`, `diffPreview`, and `patchPreview` are removed from the transcript view (a result's content is fetched with the `content` query), a tool item's `text` is now its presentation's title and how the call ended (`$ npm test (completed)`), and the live `tool` item's `partial` carries only `content` (`partial.details` and its `toolDetailsMaxSerializedBytes` limit are removed): read a running call's progress from its `presentation` and `patch`.
