### Gondolin dependency copies

Both root and standalone example locks retain Gondolin 0.12.0 and now select `node-forge` 1.4.2 and Undici 6.29.1. Only those two entries changed in each graph. The standalone manifest/lock were resolved and installed outside the workspace; root script-free installation and isolated `npm ci --ignore-scripts` passed. No install scripts or VM were run. Gondolin's pre-existing Node >=23.6 requirement is example-specific, not a new product runtime requirement.

Bounded local checks passed against both installed copies: RSA signatures accepted the original message and rejected a changed message; a generated self-signed certificate round-tripped and verified; Undici fetched a loopback HTTPS response with an explicit test CA and rejected that certificate without the CA. A locally signed malformed nested DigestAlgorithm was rejected, with a valid DER encoding as the positive control.

The isolated npm audit reported zero advisories on 2026-11-03. However, [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv) still says affected `<=1.4.0` and patched versions “None.” [Upstream PR #1152](https://github.com/digitalbazaar/forge/pull/1152) describes the nested-element fix but is closed **without merge**. The scanner result and bounded rejection test are evidence for the installed release, not proof of comprehensive cryptographic safety or proof that that PR shipped. Keep this metadata discrepancy in the maintainer's post-merge reconciliation; do not dismiss alerts solely because the version increased.
